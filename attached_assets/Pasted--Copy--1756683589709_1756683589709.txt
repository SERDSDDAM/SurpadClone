شرح المشاكل التي واجهتنا لتشغيل المشروع
واجهنا عدة مشاكل رئيسية خلال محاولتنا تشغيل المشروع، سأشرح كل مشكلة والحل الذي تم تطبيقه لها:

1. مشكلة توافق إصدار Python مع الحزم المطلوبة
المشكلة:
عند محاولة تشغيل المشروع باستخدام الأمر docker-compose -f docker-compose.phase1.yml up -d، ظهر خطأ يتعلق بتوافق إصدار Python مع الحزم المطلوبة في ملف requirements.txt. كانت رسالة الخطأ تشير إلى أن Python 3.5 أو أحدث مطلوب، بينما الصورة المستخدمة geodata/gdal:latest كانت تستخدم Python 3.4.

السبب:
الصورة الأساسية geodata/gdal:latest تستخدم إصدار Python قديم (3.4) بينما العديد من الحزم في ملف requirements.txt تتطلب إصدار Python 3.5 أو أحدث.

المحاولات للحل:

حاولنا تثبيت إصدار أقدم من pip (pip<21.0) يتوافق مع Python 3.4، لكن هذا لم يحل المشكلة.
حاولنا تغيير الصورة الأساسية إلى osgeo/gdal:ubuntu-full-latest، لكن هذه الصورة لم تكن موجودة.
الحل النهائي:
لم نتمكن من حل هذه المشكلة بشكل كامل، لكننا تجاوزناها باستخدام ملف docker-compose.dev.yml الذي يحتوي فقط على الخدمات الأساسية (PostgreSQL، Redis، MinIO) بدون خدمات العامل (worker) والموزع (dispatcher) التي تسبب المشكلة.

2. مشكلة تشغيل التطبيق على نظام Windows
المشكلة:
عند محاولة تشغيل التطبيق باستخدام الأمر npm run dev على نظام Windows، ظهر خطأ يقول: 'NODE_ENV' is not recognized as an internal or external command, operable program or batch file.

السبب:
صيغة تعيين متغير البيئة NODE_ENV=development هي صيغة Linux/Unix ولا تعمل مباشرة على نظام Windows.

الحل:

قمنا بتثبيت حزمة cross-env التي تسمح بتعيين متغيرات البيئة بطريقة تعمل على جميع الأنظمة.
عدلنا ملف package.json لاستخدام cross-env في أوامر التشغيل:
json
 Copy
 Insert
 Export

"dev": "cross-env NODE_ENV=development tsx server/index.ts",
"start": "cross-env NODE_ENV=production node dist/index.js"
3. مشكلة عدم تحميل متغيرات البيئة
المشكلة:
بعد حل مشكلة تشغيل التطبيق على Windows، ظهر خطأ جديد يشير إلى أن متغير البيئة DATABASE_URL غير معرّف: Error: DATABASE_URL must be set. Did you forget to provision a database?

السبب:
التطبيق لم يكن يقوم بتحميل متغيرات البيئة من ملف .env إلى process.env. رغم وجود ملف .env يحتوي على جميع المتغيرات المطلوبة، إلا أن التطبيق لم يكن يقرأه.

المحاولات للحل:

حاولنا استخدام import "dotenv/config" لتحميل متغيرات البيئة، لكن هذا لم ينجح في بيئة ES Modules.
الحل النهائي:

قمنا بتثبيت حزمة dotenv.
عدلنا ملف server/index.ts لاستخدام دالة config() من حزمة dotenv لتحميل متغيرات البيئة:
typescript
 Copy
 Insert
 Export

import { config } from "dotenv";

// Load environment variables
config();
