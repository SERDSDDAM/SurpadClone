## المرحلة 1: الذكاء السياقي التلقائي (Context-Aware Intelligence)  
### (الأسبوعان 1–2)

> “تفعيل/إلغاء الصلاحيات تلقائياً حسب المشروع/الموقع/الوقت/حالة الطوارئ.”

### الأهداف
- ✅ تفعيل صلاحيات تلقائياً عند فتح ملف مشروع.
- ✅ تعطيل صلاحيات خارج ساعات العمل أو الموقع الجغرافي.
- ✅ تفعيل “وضع الطوارئ” آلياً عند الكوارث.

### المهام التنفيذية
1. ✅ إضافة حقل `context_triggers` في جدول `users` أو `user_assignments`:
   ```ts
   context_triggers: {
     project_id?: string,
     location_bbox?: [number, number, number, number], // GPS bounds
     working_hours?: { start: '08:00', end: '17:00' },
     emergency_level?: 1 | 2 | 3 | 4 | 5
   }
   ```

2. ✅ تحديث middleware `requirePermission` ليتحقق من السياق:
   ```ts
   if (permission.requiresLocation && !isInBoundingBox(user.location, assigned.bbox)) 
     return res.status(403).json({ error: 'Access denied: Location restricted' });
   ```

3. ✅ إنشاء خدمة `ContextAwareService.ts`:
   - تستمع لأحداث: `project.opened`, `user.location.changed`, `emergency.activated`.
   - تُفعّل/تُلغي الأدوار تلقائياً.

4. ✅ واجهة إدارة: `/admin-context-triggers`
   - نموذج لإضافة/تعديل المشغلات السياقية.
   - خريطة تفاعلية لتحديد BBOX جغرافي.

### المخرجات
- 🎯 صلاحيات تُفعَّل فقط عند الحاجة.
- 📍 منع الوصول خارج النطاق الجغرافي/الزمني.
- 🆘 تفعيل تلقائي لصلاحيات الطوارئ.

### مؤشرات النجاح
- ✔️ 80% من الصلاحيات تُفعَّل/تُلغى تلقائياً حسب السياق.

## المرحلة 2: التحليل السلوكي والتنبؤ بالمخاطر (Behavioral Analytics & Risk Prediction)  
### (الأسبوعان 3–4)

> “كشف الأنماط غير الطبيعية قبل حدوث الضرر — مثل: مستخدم يفتح 50 طلب قرار مساحي في ساعة واحدة.”

### الأهداف
- ✅ كشف السلوك غير الطبيعي (عدد الطلبات، وقت غير عادي، موقع مختلف).
- ✅ تصنيف المخاطر (Low/Medium/High/Critical).
- ✅ إجراءات تلقائية (تنبيه، تعليق مؤقت، طلب مصادقة إضافية).

### المهام التنفيذية
1. ✅ توسيع جدول `audit_logs` بإضافة metadata:
   ```ts
   metadata: {
     ip_address: string,
     device_fingerprint: string,
     request_count_last_hour: number,
     location_changed: boolean
   }
   ```

2. ✅ إنشاء خدمة `RiskAnalyzerService.ts`:
   ```ts
   function calculateRiskScore(log: AuditLog): number {
     let score = 0;
     if (log.metadata.request_count_last_hour > 30) score += 5; // High activity
     if (log.hour < 6 || log.hour > 22) score += 3; // Unusual time
     if (log.metadata.location_changed) score += 4; // Suspicious location change
     return score;
   }
   ```

3. ✅ تحديث middleware `requirePermission`:
   ```ts
   const riskScore = await riskAnalyzer.calculate(user.id);
   if (riskScore > 7) {
     await sendAlertToAdmin(user.id, 'High risk activity detected');
     return res.status(403).json({ error: 'High risk: Access temporarily suspended' });
   }
   ```

4. ✅ لوحة “مراقبة المخاطر” في `/admin-dashboard-enhanced`:
   - قائمة المستخدمين حسب مستوى الخطر.
   - زر “تعليق مؤقت” أو “مراجعة صلاحيات”.

### المخرجات
- 👁️ كشف تلقائي للتهديدات الداخلية.
- 📊 تصنيف ديناميكي للمخاطر.
- ⚠️ إجراءات وقائية تلقائية.

### مؤشرات النجاح

## المرحلة 3: التفويض الذكي الديناميكي (Dynamic Delegation Engine)  
### (الأسبوعان 5–6)

> “تفويض شرطي + تصعيد تلقائي + تفويض طوارئ — بدون تدخل إداري.”

### الأهداف
- ✅ تفويض مشروط (مثال: يمكن الموافقة فقط إذا كانت المساحة < 200m²).
- ✅ تصعيد تلقائي (إذا لم يرد المدير خلال 24h → ينتقل لنائبه).
- ✅ تفويض طوارئ (عند غياب المدير → يُفعّل للموظف الأقدم).

### المهام التنفيذية
1. ✅ توسيع جدول `delegations`:
   ```ts
   conditions: JSON, // { max_area: 200, min_approval_level: 'section_head' }
   escalation_rules: JSON, // { timeout_hours: 24, escalate_to: 'deputy.director' }
   emergency_trigger: boolean // auto-activate if user is absent
   ```

2. ✅ إنشاء خدمة `DelegationEngine.ts`:
   ```ts
   async function checkDelegationConditions(userId, permission, requestData) {
     const delegation = await db.delegations.find({ userId, permission });
     if (!delegation) return false;
     
     // Check conditions
     if (delegation.conditions.max_area && requestData.area > delegation.conditions.max_area) 
       return false;
     
     // Check escalation
     if (delegation.escalation_rules) {
       const hoursPassed = (Date.now() - delegation.created_at) / 3600000;
       if (hoursPassed > delegation.escalation_rules.timeout_hours) {
         return await delegateTo(delegation.escalation_rules.escalate_to);
       }
     }
     
     return true;
   }
   ```

3. ✅ تحديث واجهة `/admin-advanced-rbac`:
   - نموذج “تفويض متقدم” مع شروط وتصعيد.
   - تقويم لجدولة التفويضات المؤقتة.

### المخرجات
- 🔁 تفويضات ذكية تتكيف مع السياق.
- ⏳ عدم تعطيل سير العمل بسبب الغياب.
- 🛡️ تحكم دقيق حتى في التفويضات.

### مؤشرات النجاح
- ✔️ 70% من التفويضات تستخدم شروطاً ديناميكية.
- ✔️ زمن استجابة للموافقات < 24 ساعة.
