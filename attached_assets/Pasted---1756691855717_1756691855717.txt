سأُعدّ لك **خطة إدارة المستخدمين والصلاحيات** بتصميم تقني واضح، يعكس الهيكل الإداري، ويضمن التحكم الدقيق في الوصول إلى الميزات حسب الرتبة والمسؤولية.

# 🏗️ خطة إدارة المستخدمين والصلاحيات – "بنّاء اليمن"

## ✅ الهدف
بناء نظام صلاحيات (RBAC) متكامل يُعَدّل على أساس الهيكل التنظيمي لـ **مكتب الأشغال العامة والطرق**، بحيث:
- يُعطي كل مستخدم فقط الصلاحيات اللازمة لأداء وظيفته.
- يُمكن التوسع لاحقاً مع إضافة أدوار جديدة (مثل: فروع المديريات).
- يدعم التفويض بين الأقسام (مثلاً: نائب المدير العام يمكنه إصدار قرارات في نطاق اختصاصه).

## 📂 2. هيكل الصلاحيات (Permissions)

### 🔹 أولاً: تصنيف الصلاحيات حسب الوظيفة

#### 🌐 **الوصول العام**
- `view_dashboard`: عرض لوحة التحكم
- `view_reports`: عرض التقارير
- `export_data`: تصدير البيانات (Excel/PDF)
- `search_users`: البحث في المستخدمين

#### 🛠️ **إدارة المستخدمين**
- `create_user`: إنشاء مستخدم جديد
- `edit_user`: تعديل بيانات المستخدم
- `delete_user`: حذف مستخدم
- `assign_role`: تعيين/تعديل دور المستخدم
- `reset_password`: إعادة تعيين كلمة المرور

#### 🧩 **إدارة الأدوار والصلاحيات**
- `manage_roles`: إنشاء/تعديل/حذف أدوار
- `manage_permissions`: تعيين صلاحيات للأدوار

#### 🗺️ **الخدمات الجغرافية (GIS)**
- `upload_file`: رفع ملفات (GeoTIFF, Shapefile)
- `view_layer`: عرض طبقة جغرافية
- `edit_layer`: تعديل طبقة جغرافية
- `publish_layer`: نشر طبقة للجميع
- `digitize`: استخدام أداة الرقمنة
- `request_decision`: تقديم طلب قرار مساحي
- `approve_decision`: الموافقة على القرار المساحي
- `reject_decision`: رفض القرار المساحي

#### 💼 **إدارة المشاريع**
- `create_project`: إنشاء مشروع
- `edit_project`: تعديل المشروع
- `assign_worker`: تعيين مسؤول للمشروع
- `submit_report`: تسليم تقرير تنفيذ
- `review_project`: مراجعة المشروع
- `close_project`: إغلاق المشروع

#### 📄 **إدارة الملفات والمستندات**
- `upload_document`: رفع مستند
- `view_document`: عرض مستند
- `edit_document`: تعديل مستند
- `delete_document`: حذف مستند
- `share_document`: مشاركة مستند مع مستخدم آخر

#### 📊 **التحليلات والتقارير**
- `generate_analytics`: إنشاء تقارير تحليلية
- `view_analytics`: عرض التقارير
- `export_analytics`: تصدير التقارير

#### 🔐 **الأمان والسجلات**
- `view_audit_log`: عرض سجلات الأنشطة
- `view_security_alerts`: عرض تنبيهات الأمان
- `ban_user`: حظر مستخدم مؤقتاً

## 🧱 4. التصميم التقني (Database Schema)

### 🔹 جداول النظام

```ts
// users.ts
export const users = pgTable('users', {
  id: uuid('id').defaultRandom().primaryKey(),
  username: text('username').notNull().unique(),
  passwordHash: text('password_hash').notNull(),
  displayName: text('display_name'),
  role: text('role').notNull().check(roleCheck), // 'admin', 'deputy_admin_1', ...
  email: text('email').unique(),
  phone: text('phone'),
  isActive: boolean('is_active').default(true),
  createdAt: timestamp('created_at').defaultNow(),
  updatedAt: timestamp('updated_at').defaultNow().onUpdateNow(),
});

// roles.ts
export const roles = pgTable('roles', {
  id: uuid('id').defaultRandom().primaryKey(),
  name: text('name').notNull().unique(), // 'admin', 'deputy_admin_1', ...
  description: text('description'),
  level: integer('level').notNull(), // 0 to 5
});

// permissions.ts
export const permissions = pgTable('permissions', {
  id: uuid('id').defaultRandom().primaryKey(),
  name: text('name').notNull().unique(), // 'upload_file', 'view_layer', ...
  description: text('description'),
});

// role_permissions.ts
export const rolePermissions = pgTable('role_permissions', {
  roleId: uuid('role_id').references(() => roles.id, { onDelete: 'cascade' }),
  permissionId: uuid('permission_id').references(() => permissions.id, { onDelete: 'cascade' }),
  primary: primaryKey({ columns: [roleId, permissionId] }),
});
```

## 🛠️ 5. middleware للتحقق من الصلاحيات

```ts
// server/middleware/auth.ts
import { requireAuth } from './auth.js';

export function requireRole(...roles: string[]) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!req.user) return res.status(401).json({ error: 'Unauthorized' });
    if (!roles.includes(req.user.role)) return res.status(403).json({ error: 'Forbidden' });
    next();
  };
}

// مثال: للوصول إلى /api/gis/decisions/approve
router.post('/approve', requireAuth, requireRole('deputy_admin_technical', 'deputy_admin_inspection', 'manager'));
```

## 📦 7. دمج مع نظام المصادقة

- عند تسجيل الدخول، يتم تحقق من `username` و`password`.
- إذا نجح، يتم إرسال توكن JWT يحتوي:
  ```json
  {
    "id": "uuid",
    "username": "surveyor1",
    "role": "staff",
    "exp": 1234567890
  }
  ```
- عند كل طلب، يُفحص التوكن باستخدام `requireAuth` ثم `requireRole`.
